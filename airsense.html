How it works

Four stages from a board in a box to a device reporting data.

  1. 01

    Connect

    Plug the device into your computer with a USB data cable.

  2. 02

    Flash

    Install production firmware from this page. Two to three minutes.

  3. 03

    Provision

    Configure the Gateway’s network, or let a Sensor Node pair itself.

  4. 04

    Deploy

    Mount the hardware in its target room and confirm it is reporting.

After flashing

Provisioning

Flashing puts the firmware on the board. Provisioning is what tells it where it is and who it belongs to.

Gateway

Needs facility WiFi and a tenant secret. One-time, done from a phone or laptop.

  1. 01
    Power on
    On a first boot the Gateway broadcasts its own temporary WiFi network.
  2. 02
    Join the setup network
    Connect a phone or laptop to AirSense-Setup-XXXXXX.
  3. 03
    Configure
    A setup page opens by itself. Enter the facility WiFi credentials and the tenant’s ingest secret.
  4. 04
    Reboot
    The Gateway restarts onto the facility network.
  5. 05
    Forwarding
    Readings start reaching the backend. Nothing further to configure.

Reconfiguring a unit already in service: hold BOOT for 3 seconds at power-up to reopen the setup page.

Sensor Node

Nothing to type in. The node finds its Gateway and names itself.

  1. 01
    Power the node
    Mains or USB. Sensor Nodes stay awake so the gas sensor keeps its warm-up.
  2. 02
    Open the pairing window
    Open for a few minutes after every Gateway boot, or reopened anytime with a quick tap of the Gateway’s button.
  3. 03
    The node finds the Gateway
    Discovery is automatic — no Gateway address or radio channel to enter.
  4. 04
    It pairs and names itself
    The node takes an ID from its own hardware address, for example node-A1B2C3.
  5. 05
    Assign a room
    It appears under “Newly Detected” on the dashboard’s Devices page. Name it and assign it there.

A USB serial console is available for advanced use — see Advanced, below.

Having trouble?

The common ones first. Deeper engineering detail is under Advanced.

USB device not detected
  1. Check the cable carries data — many charging cables have power lines only.
  2. Close the Arduino IDE if it is open.
  3. Close any PlatformIO serial monitor.
  4. Try another USB port, ideally directly on the machine rather than through a hub.
  5. Unplug the device and reconnect it, then try again.
Flashing failed part way through
  1. Leave the device plugged in and start the install again — a partial write is recoverable, the board is not bricked.
  2. Swap the USB cable. Marginal cables commonly fail mid-write rather than at connect.
  3. Avoid a USB hub for the retry.
The browser cannot access the serial port

Installing needs Web Serial, which today means Chrome, Edge or Opera on a desktop machine. Firefox, Safari and mobile browsers do not support it.

Web Serial also requires a secure connection, so the page must be served over HTTPS.

The Gateway will not join the facility WiFi
  1. Hold BOOT for 3 seconds at power-up to wipe the saved configuration and reopen the setup page.
  2. Reconnect to AirSense-Setup-XXXXXX and re-enter the credentials.
  3. Confirm the network is 2.4 GHz — the ESP32 does not join 5 GHz networks.
A Sensor Node will not pair
  1. Confirm the Gateway’s pairing window is open — tap the Gateway’s button to reopen it.
  2. Power-cycle the Sensor Node while that window is open.
  3. Move the node closer to the Gateway for the initial pairing.
Which Gateway firmware do I install?

Choose by the screen on your board, and the installer asks you before it writes anything:

  • Touch + Audio Alerts — a CYD with a working touchscreen. This is the normal choice.
  • Auto-Scroll — a CYD clone or plain display with no touch controller fitted. Same dashboard, advancing to the next node’s page every 5 seconds instead of on a tap.

Advanced

Engineering detail, kept out of the main flow rather than removed.

Gateway hardware and firmware detail
BoardCYD (ESP32-2432S028R) — 2.8″ ILI9341. A headless plain ESP32 with an SD card is also supported.
RadiosDirect wireless link to the room nodes, plus WiFi for the backend uplink.
Touch buildFull touch interface — Home, per-node pages (Overview, Air Quality, Environment, Alerts, Node Info), live Alerts, and on-device Settings (theme, brightness, thresholds, sound, pairing, factory reset).
Auto-scroll buildSame dashboard, advancing to the next node’s page every 5 seconds — for a CYD clone or plain ILI9341 with no XPT2046 touch controller.
Audible alertsNew in v2.1. A 35 × 25 mm 8 Ω speaker plugs into the board’s own speaker socket — no soldering. Sounds a two-beep warning, or a four-beep alarm that repeats until acknowledged, when a room crosses a threshold; plus boot, pairing and touch feedback. Adjustable and fully silenceable from Settings > Sound. Optional: with no speaker fitted the firmware behaves exactly as v2.0.0 did.
Offline resilienceMicroSD backlog with automatic replay once WiFi returns — no data lost during an outage.
ProvisioningWiFi setup page on first boot; hold BOOT for 3 seconds to reconfigure.
Sensor Node hardware and firmware detail
BoardESP32-C3. This build’s wired unit: SDA → GPIO8, SCL → GPIO10.
SensorsENS160 (eCO₂ and TVOC) with an AHT21 (temperature and humidity), on I²C.
RadioDirect wireless link to the Gateway only — this device never joins your WiFi network.
PowerMains or USB, always on. The ENS160 needs continuous warm-up.
Send cadenceAn averaged reading every 5 seconds, with a RAM retry buffer if the Gateway is briefly unreachable.
ProvisioningAutomatic, during the Gateway’s pairing window.
Serial console

A Sensor Node exposes a USB serial console at 115200 baud:

  • help — list commands
  • show — current pairing status
  • set deviceid <value> — rename without re-pairing
  • pair — force a fresh pairing search, the same effect as holding BOOT for 3 seconds at power-up

Close the console before flashing — it holds the serial port open and the installer will not be able to claim it.
